# Agent Run Ledger schema v1

The ledger is `events.jsonl` under the Git common directory's `speckit-runs/<run-id>/`. It is local to the clone, outside every worktree and Git tracking. Removing a worktree does not remove it. Each line is one object with exactly `schema_version`, `run_id`, `feature`, `sequence`, `observed_at`, `event_id`, `kind`, `source`, and `data`. `schema_version` is `1`. Sequence starts at 1 and increases by one. Event IDs are unique per run; imported runner IDs use the source log line number so retry is idempotent. A conflicting duplicate, unknown field, malformed line, or unsupported version invalidates the stream; reading never repairs it.

`data` uses the fixed per-kind field allowlist in `ledger.py` (`FIELDS`). Kinds are `run`, `step`, `gate`, `route`, `classifier`, `escalation`, `review`, `finding`, `verification`, `convergence`, `usage`, `human_action`, and `snapshot`. Sources are `runner`, `client-counter`, `operator-attested`, and `agent-reported`. The source label records provenance, not an attestation that a local process cannot be forged. An `agent-reported` identity alone cannot establish independent review, actual model, or human action. `usage` requires a `client-counter` source, a bounded source label, a SHA-256 digest of the client counter artifact, and complete non-overlapping invocation scopes to contribute to totals. A digest makes the claim auditable; it does not authenticate who submitted it.

The launcher records the runner snapshot at invocation end. Its local archive also stores `invocation.json` with only the exit status and ending log-line count. If that status is 130 while a gate is waiting, a state value of `reject` is recorded as `unobserved`: Spec Kit can produce that value on Ctrl-C without a human rejection. A manual `ledger.py import` can use the archived status to recover this distinction, but does not claim to have observed the invocation-end tree; use `snapshot` for a separate operator observation.

The schema accepts IDs, bounded labels, nonnegative counters, booleans, and digests only. Status, verdict, severity, resolution, route source, profile, effort, and action fields use the fixed enumerations in `ledger.py` (`ENUM_FIELDS`); unrecognized spellings fail validation. It has no free-form message, command argument, prompt, stdout/stderr, raw review prose, secret, account, quota, or campaign-content field. Raw agent logs retain the existing local-only handling. `run` and `step` observations come from the archived Spec Kit log and state snapshot. Gate choice is captured only from that invocation's final state, then attached to its last newly imported gate occurrence. A choice skipped before resume remains unavailable. The importer also records a runner snapshot at invocation end; a later changed tree or feature digest makes earlier final acceptance stale even when the worktree is subsequently removed.

Review and convergence observations bind to the implementation tree plus current spec, intent, plan, tasks, and manifest digests. `alternate_available` belongs to a specific `review_id`; the report distinguishes it from actual cross-provider use. A rejected plan gate requires a changed plan/spec, passing verification, an independent approved review bound to those digests, and a manual recovery action before later approval counts as compliant. A rejected tasks gate requires changed tasks, a passing `speckit-analyze` check, and manual recovery. Agent-reported checks or convergence do not prove compliance. Once the worktree is removed, current compliance and AC pass status become unavailable; historical events remain readable.

A rejected `approve-intent` gate requires a changed spec digest, an operator-attested passing `validate-clarified-spec` check, and manual recovery before reapproval. Since the workflow writes `intent.md` after the gate, the later runner import must then show completed `record-intent` and successful `validate-intent` steps plus a runner snapshot containing an intent digest bound to the revised spec.

Runner and operator snapshots remain recordable during a spec revision even when the current manifest cannot yet validate against `intent.md`. The report then marks the manifest unavailable or stale. A passing verification is bound to the current spec digest; an older clarified-spec check cannot prove a revised spec.

Usage totals require complete, disjoint counters for every recorded route attempt and classifier invocation. A missing counter makes totals and dependent ratios unavailable. A `(stage, cause_id, attempt)` route observation must be unique; duplicate or contradictory observations invalidate the stream and cannot manufacture an underpowered signal. Rework spans begin with an evidenced reasoning failure, mechanical failure, or rejected attempt and end at an observed successful correction; only repeated distinct reasoning failures can form an underpowered signal.

The archive also keeps the workflow definition, parsed default routing-policy rows with a digest, and validated AC manifests under `manifests/<sha256>.json`. `acceptance-evidence.json` in a feature directory maps every approved `AC-NNN` to named `unittest` methods; the tracked manifest is a definition, never test results or ledger data. A revised valid mapping creates another immutable archive version. The latest snapshot selects the current version, and checks tied to older versions become stale. `./scripts/check` and `./scripts/verify` are suite-wide verification only. An individual AC passes only when all mapped methods pass for the same implementation snapshot and manifest version. Reports label absent or unreliable evidence unavailable rather than inventing values.

Use `.agentic/spec_workflow/ledger.py import RUN_ID`, `record RUN_ID KIND --source SOURCE --data JSON`, `snapshot RUN_ID`, and `check RUN_ID AC-NNN tests.test_module.TestCase.test_method` for local recording. Use `./scripts/agent-metrics --run RUN_ID`, `./scripts/agent-metrics specs/N-slug`, or `./scripts/agent-metrics --all` for reports; add `--json` for machine-readable output. A corrupt stream produces diagnostics and a nonzero exit. The tool does not invoke a model or change routing defaults.

Generated by `ballast init` from the repository's evidence. Each value names its source; a value marked `TO CONFIRM` or `inferred` has none yet. Review it, amend it to fit the project, and commit it: this file is project-owned and Ballast never overwrites it.

## Core principles

1. **Projects own only their files.** The project commits `ballast.toml`, this constitution, `docs/policies/project/` and its own code and documents. Everything Ballast installs (`.ballast/`, `.specify/` except `memory/`, `bugs/` and `assessments/`, installed skills and `docs/policies/*.md`) is git-ignored and rebuilt by `ballast setup`.
2. **Specifications and decisions govern intent.** An accepted architecture document, accepted ADRs and a ready feature spec define what the project builds. Current code is evidence of behavior, not permission to supersede a decision; a conflict is recorded and resolved explicitly.
3. **Executable evidence before acceptance.** Every acceptance criterion has a test or other recorded verification, and the project's gates pass before a change is accepted. A failing test, validation or lint rule is never silently weakened.
4. **No secrets or local destinations in tracked files.** Credentials, tokens, hostnames, IP addresses and server paths stay out of code, logs, examples, commits, issues and pull requests.
5. **Protected inputs and operator-only trust.** `ballast.toml`, `.specify/` and `.ballast/spec_workflow/` decide what workflow runs execute. Only the operator reviews them and runs `ballast trust`; an agent never gains more authority than its caller.

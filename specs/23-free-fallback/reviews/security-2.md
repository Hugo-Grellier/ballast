# Independent security review: local zero-cost fallback (#23)

- Review: security, independent (R2: new execution backend, privacy boundary for repository content, headless permission model). Second review after [security.md](security.md); different model from the author and from the first reviewer (claude-fable-5-1; the implementation and the first review were claude-opus-5-5 / claude-sonnet-5-5). Agent-provisional, not human approval.
- Method: `.agents/skills/ballast-security-review/SKILL.md`, `docs/policies/security.md`, invariants BL-INV-002/003/005; the diff `origin/main...HEAD` (`fallback.py`, `agent.py`, `autonomy.py`, `ledger.py`, `artifacts.py`, `run.py`, tests); ADR-0014; spec, plan, research R1 to R10, contracts, DEC-0001 to DEC-0004, evaluation.md, live-check.md. Static trace of every path from the primary's exit to the fallback's `Popen`, plus one scratch experiment on the bubblewrap argv (below). No environment value or credential was printed; no `ballast` command ran in this worktree.
- Traced: an operator who opts in; an agent that tries to enable, widen or redirect the fallback through anything it can write (worktree, `.gitignore`, `.codex/`, `.agents/skills`, env of a nested wrapper, `SPECKIT_WORKFLOW_RUN_ID`); a primary that prints a quota signature; a primary that mutates tracked, untracked, ignored, `.git` and ref state before failing; a cloud, remote, renamed or replaced model; proxy and endpoint leftovers; the Codex configuration layers; what the fallback process can read under bubblewrap and without it; ledger forgery and review provenance.

## Examined and held

- **Privacy: the model request goes only to loopback.** The endpoint is a literal `http://127.0.0.1:11434` with no option, setting or field to change it (DEC-0003); `--local-fallback-endpoint` is refused by name. `fallback_env` starts from `confined_env(env, None)` (every secret-named variable gone, including both CLIs' keys), pops `CODEX_OSS_BASE_URL`, `CODEX_OSS_PORT`, `OLLAMA_HOST` (the only overrides the pilot found in the binary) and every proxy variable in any case, then sets the proxy variables to `127.0.0.1:9` with `NO_PROXY` on loopback. Codex's own `ollama` provider refuses a `-c model_providers.ollama.*` override and ignores `oss_base_url` (pilot item 2), and `-c` tokens cannot appear in the argv anyway. The probes use `ProxyHandler({})`, a literal IP (no DNS), capped bodies, one 10 s budget, and send only the model name. The user Codex layer is a fresh 0700 `CODEX_HOME` with no `config.toml`, so `mcp_servers`, `notify`, profiles and project trust are all empty; `/etc/codex/*` and a project `.codex/config.toml` refuse. A `:cloud`/`-cloud` tag, or `remote_model`/`remote_host` in `/api/tags` or `/api/show`, refuses. The start-up egress to `chatgpt.com`/`github.com` (first review F-002) is blackholed by the proxy variables and the ADR, policy and technical spec now call this a reduction, not a boundary, which is accurate; port 9 is privileged, so an agent cannot stand up a listener there.
- **Permission: exact argv, no agent-controlled token.** `fallback_argv` is `permission_args("codex", ["exec", prompt])` plus five fixed tokens; `codex` comes from `trusted_program` (never a worktree or temp copy), the model from the operator file (validated against `ledger.MODEL`, no leading `-`), the prompt from the Spec Kit workflow definition under protected `.specify/` (translated `/` to `$` only). The primary's `args[2:]` are never forwarded. `permission_mismatch` is tautological by construction (it compares against the same builder), as the ADR admits; `test_fallback_argv_literal_tokens` is what actually pins the profile. Under bubblewrap the fallback uses the same `confined_argv(integration="codex")` as a primary Codex step; without it, the same systemd scope plus Codex's own `workspace-write`, `network_access=false`, `writable_roots=[]`. Both sandbox probes (`codex_sandbox_nests` / `codex_sandbox_starts`) run with the fallback's env and a scratch home before any prompt. stdin is closed, the `--json` stream must parse, `turn.failed` fails, `BLOCKED_*` in the agent message fails the step.
- **Eligibility: first attempt only, nothing changed, bounded.** `first = attempt == 1 and not refusals`; a draft-retry attempt records its cause and never falls back; `_fallback_step` runs `_attempt_in` once and a refused draft after it is `EXIT_LIMIT` with no retry (SC-005 holds). `classify` puts the reserved codes (blocked, tampered or uncontained, limit, interrupted, auth) before the signatures, which are matched only in the last 64 KiB of each stream. The state evidence covers tracked and untracked content (`tree_digest`), reviews, drafts, every git-ignored path by lstat metadata (bounded, link-safe, protected inputs excluded), and `HEAD` plus every ref; any piece that cannot be established refuses. `.git` internals (config, hooks, index) are not in the evidence, but bubblewrap binds the admin directory read-only (`_git_binds`) and the human-gated Claude settings deny `Edit(./.git/**)` with no free-form Bash, so a primary cannot write there in either mode. The step is counted (`_autonomous_run`) before the fallback starts; an exhausted limit stops with the existing refusal.
- **Setting: outside agent reach.** `fallback.json` lives in `state_dir(root)/runs/<run>`, which refuses the checkout and every temp root (#48, #49); it is read `O_NOFOLLOW`, size-capped, exact field set, anything invalid is off. Chat runs refuse the flag at the CLI and the wrapper (`workflow == CHAT`). No environment variable or `ballast.toml` key enables it.
- **Ledger and provenance.** `route`/`usage` events hold enumerated labels and counters only; `events.jsonl` lives under the git common dir (`speckit-runs/`), read-only under bubblewrap and denied to the human-gated Claude step. Fixed event IDs make repeats idempotent. `artifacts.py` takes the fallback draft's provider and model from the wrapper's step entry, not the agent's report; `ledger.report` and the Chat report set `cross_provider: false` run-wide whenever a runner `route_source: fallback` succeeded on a `ballast-review` stage. An agent that forges such a route can only lower the claim.

## Findings

### SEC2-001 (low, implementation-bug): the Autonomous fallback is handed the operator's Codex access token it does not need

- Location: `tools/spec_workflow/agent.py:1490` (`confined_argv(..., integration="codex")` for the route) with `tools/spec_workflow/autonomy.py:_agent_home_binds`.
- Evidence: scratch call of `confined_argv(root, [...], private=P, home=H, env={"CODEX_HOME": <private home>}, integration="codex")` with `H/.codex/auth.json` present produced `--ro-bind P/codex-auth-1.json H/.codex/auth.json`, and `P/codex-auth-1.json` held the access token (refresh token blanked). `ConfinementCompositionTests` never creates `~/.codex/auth.json`, so this is untested.
- Why it matters: `--oss` needs no login (pilot items 9 and 10), and in a Claude-primary run the primary never saw this credential, so for that run the fallback's model reads strictly more than the primary did. A prompt-injected local model with `cat` and workspace-write can copy the token into the worktree, where a later step may commit it. The first review (F-003) accepted this because changing the overlay would make the fallback's confinement "differ" from the primary's; AC-004 and BL-INV-003 forbid a *wider* confinement, not a narrower one, so that rationale does not hold.
- Bound: Autonomous only (the human-gated path has no overlay and every human-gated step can read the home); on the qualified host Autonomous refuses before this point. Hence low.
- Fix: do not copy any login for the route (one flag on `_agent_home_binds`/`confined_argv`, e.g. `login=False` when `route is not None`; the throwaway overlays stay so the sandbox shape is unchanged). Regression: extend `ConfinementCompositionTests` with `~/.codex/auth.json` present and assert no `codex-auth-*` file and no `auth.json` bind.

### SEC2-002 (low, architecture-issue): the model is trusted by name against an unauthenticated, mutable local service

- Location: `tools/spec_workflow/fallback.py:_checks` steps 7, 8 and 11a; `write_setting`.
- Sketch: Ollama's loopback API has no authentication. Any local process can `POST /api/create` (a Modelfile `FROM qwen3:4b` with a hostile `SYSTEM` prompt and `PARAMETER num_ctx 16384`) or `/api/copy` under the operator's exact model name. The probes then see an installed model with a nonzero size and digest, no remote fields and a sufficient `num_ctx`, and every later fallback step, review steps included, runs on the poisoned model, across runs. Whether a copy of a cloud model keeps `remote_host`/`remote_model` is also unverified (evaluation item 3).
- Who can reach the API: the operator's other processes, and in a human-gated run a Claude primary that obtains code execution (for example a new file under `.specify/scripts/python/`, which the allow rule `Bash(python3 .specify/scripts/python/*)` runs; that is caught as tampering only after the step, and the model store change persists). A Codex primary cannot (`network_access=false` closes loopback); under bubblewrap neither can. This is not a widening of agent authority, so low; it is the one input of the new boundary that an operator did not pin and that something other than the operator can change.
- Fix: pin identity at opt-in. `write_setting` records the `/api/tags` digest of the named model (the launcher runs operator-side and may query loopback), and check 7 refuses on a digest mismatch with `unknown-free-status`; or accept `MODEL@sha256:...` on the command line. Cost: one more field and one comparison.

### SEC2-003 (info, implementation-bug): `_layers_absent` checks one project file

- `tools/spec_workflow/fallback.py:567`. Codex 0.155 reads more than `config.toml` under a project `.codex/` (it has hooks and rules, hence `--dangerously-bypass-hook-trust`). With an empty `CODEX_HOME` the project is untrusted, so these should not load, and the flag is not in the argv; but refusing on any entry under `root/.codex` is cheaper than tracking Codex's file list. No action required for approval.

### SEC2-004 (info, spec-ambiguity): a prompt-injected primary chooses the model

Printing a signature and exiting 1 without changing anything selects the fallback, including on a review step. Nothing widens (same permissions, opt-in, counted, never retried, never cross-provider), but the small local model is the more injectable one, so a repository can steer which model completes a review. Already noted as F-004; the policy text says a fallback review is never cross-provider, which is the right record. No action.

### SEC2-005 (info): egress reduction is stated truthfully

The proxy blackhole stops Codex's start-up requests only while Codex honors the variables; the live rerun showed only loopback. The ADR, the policy and the technical spec say "reduction, not a boundary". A network namespace with a forwarded loopback socket remains the right follow-up. No action.

## Verification

- `uv run --no-project --isolated --python 3.13 --with pyyaml python -m unittest tests.test_fallback tests.test_spec_workflow`: `Ran 252 tests in 732.079s`, `OK` (2026-10-07, operator host, Linux with a systemd user session, real `bwrap`).

## Conclusion

The R2 boundary holds as designed: nothing the agent or the checkout controls can enable the fallback, redirect it off loopback, widen its argv or environment, or make a mutated tree eligible; refusals happen before any prompt is sent and are recorded. The two low findings are a credential the fallback is given without needing it (SEC2-001, Autonomous only) and a model identity that is not pinned against a mutable unauthenticated service (SEC2-002). Both are defense in depth with small fixes and neither is a disclosure path on the qualified host, where the Autonomous fallback refuses. They should be fixed or recorded as accepted residual risk in ADR-0014 before or with the merge; they do not block it.

- Verdict: approved

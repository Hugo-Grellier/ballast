# Security review: local zero-cost fallback (#23)

- Review: security (R2: a new execution backend, a second model that reads repository content, and the headless permission model). Agent-provisional, run during the operator's human-gated continuation of Autonomous run `f200c320` (not human approval).
- Reviewer: claude/claude-sonnet-5-5, driving agent; the implementation was written by an earlier agent session of the same provider family (reduced independence).
- Method: `.agents/skills/ballast-security-review/SKILL.md` and `docs/policies/security.md`, the invariants BL-INV-002, BL-INV-003 and BL-INV-005, the diff from `origin/main` (`tools/spec_workflow/fallback.py`, `agent.py`, `autonomy.py`, `ledger.py`, `artifacts.py`, `run.py`), ADR-0014, and the live check ([live-check.md](live-check.md)), including a socket and CONNECT-level observation of the real Codex process.
- Traced: the operator who opts in; a primary agent that prints a quota message to force a fallback; a malformed or agent-written setting; a model name chosen to redirect or reach the cloud; an environment that carries an endpoint override, a proxy or a secret; a hostile `~/.agents/skills`, project `.codex/config.toml` or `/etc/codex`; a model that returns an unparsable or blocked stream; a repository whose ignored tree changed during the failed attempt.

## Examined and held

- **Authority never exceeds the caller's (BL-INV-003).** The fallback argv is `permission_args("codex", ["exec", prompt])` plus the five fixed tokens, compared token for token (`permission_mismatch`) and pinned by a literal-token test; no bypass flag, extra writable root or tool network. The environment is `confined_env(env, None)` (every secret-named variable and credential location dropped, including the Anthropic and OpenAI keys) minus endpoint variables and proxies, and `permission_mismatch` is an allowlist on names and values. It runs through the primary's path: systemd scope, subreaper, bubblewrap for Autonomous steps, protected-state tamper checks, draft snapshots. Composition with #89 (per-CLI credentials) is pinned by `ConfinementCompositionTests`: the fallback's `confined_argv(integration="codex")` overlays only Codex's homes (including the private home), empties the Claude homes with a tmpfs, hides `~/.claude.json` and copies no Claude login.
- **Where the setting lives.** `fallback.json` is written by the launcher into the run's operator directory; the state-directory resolver refuses a path inside the checkout or a temp directory (observed live: the scratch run had to move its state out of `/tmp`). The reader opens it `O_NOFOLLOW`, caps its size, accepts only the exact field set and treats anything invalid as off. A model name must match the ledger model pattern, may not start with `-` and may not be a cloud tag.
- **No content leaves loopback by the model request.** The endpoint is a constant (`127.0.0.1:11434`); there is no option or setting for another (DEC-0003). Probes bypass proxies (`ProxyHandler({})`), send only the model name, cap response size and share a 10 s budget. Cloud or remote models refuse (`:cloud`/`-cloud` tags, `remote_model` and `remote_host` in `/api/tags` and `/api/show`). The check order is fixed and every unknown answer refuses.
- **Private, empty `CODEX_HOME`.** A fresh `0700` directory per fallback, removed afterwards; the user's Codex configuration, profiles, MCP servers and notify program are not read (`test_user_codex_config_not_read`). The probe refuses when `/etc/codex` is non-empty, a project `.codex/config.toml` exists, or `~/.agents/skills` is not empty. Observed live: a real home with skills refused with `permission-mismatch`.
- **Worktree state.** The fallback follows only a first attempt that changed nothing: tree, reviews, drafts, a metadata digest of every git-ignored path (lstat, never following links, protected inputs excluded, capped at 200,000 entries and 10 s) and every ref. Any piece that cannot be established refuses. Observed live: a primary that touched a tracked file refused with `changed-state`.
- **Untrusted output.** The classifier matches fixed signatures only in the last 64 KiB; the model's `--json` stream must parse, a failed turn fails the attempt, and a `BLOCKED_*` status in the agent message fails the step. The model's text is shown, never executed.
- **Ledger and logs.** `route` and `usage` events carry enumerated labels and counters only (`test_no_account_text_recorded`); no CLI text, account or quota data. Event IDs make a repeat idempotent.
- **Authority of the trigger.** An agent can make a step "fail on quota" by printing a limit message and exiting 1 without changing anything. The consequence is bounded: the operator opted in, the fallback has the same permissions as the primary, runs on a local model, is never retried and counts toward the step limit. Accepted (F-004).

## Findings

- F-001 (high, implementation-bug): the fallback environment kept the operator's proxy variables. Codex honors `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` (shown with a CONNECT logger: every request it makes went to the proxy). Reqwest does not bypass loopback by default, so a configured proxy would have received the request carrying the repository prompt, defeating the loopback guarantee, while the probes (which bypass proxies) would have passed. Required: remove every proxy variable and refuse an environment that holds one.
- F-002 (medium, implementation-bug): even with a local provider and an empty `CODEX_HOME`, the Codex CLI itself opens HTTPS connections to `chatgpt.com` and `github.com`/`api.github.com` at start-up (observed with `ss` on the real fallback process, and with a CONNECT logger). They are product services (update and feature checks), not the model request, and could not be shown to carry repository content, but ADR-0014 and the policy claimed that nothing leaves the machine. Required: stop them, or state the limit truthfully.
- F-003 (low, spec-ambiguity): the fallback runs with the same Codex login overlay as a primary Codex step (#89 copies `~/.codex/auth.json` without its refresh token for Codex steps), so the local model can read the operator's Codex access token. It has no network inside Codex's sandbox and nothing leaves loopback, so no path out was found; a Claude-primary step could receive no login at all. Not changed: it would make the fallback's confinement differ from the primary's, which AC-004 forbids.
- F-004 (info, spec-ambiguity): a prompt-injected primary can trigger the fallback (see above). Bounded; no action.
- F-005 (info, implementation-bug): the `privacy-exclusion` refusal for an endpoint variable is unreachable through the wrapper, because `fallback_env` removes the variable before the probe sees it. It stays as a defense in depth and is exercised by calling the probe directly.

## Resolution

- F-001: fixed test-first. `fallback_env` drops every proxy variable (any case), and `permission_mismatch` refuses an environment that holds one that is not the fixed blackhole value (`test_fallback_env`, `test_extra_env_refused`).
- F-002: mitigated test-first and re-observed live. The fallback environment sets `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` (both cases) to the closed local port `127.0.0.1:9` and `NO_PROXY` to loopback, so those requests fail before leaving the machine while Ollama is reached directly; `permission_mismatch` requires exactly these values (`fallback.BLACKHOLE`). This is not a network boundary (a process can ignore the variables, and Codex's own tools run with network off in its sandbox), and ADR-0014, the policy and the technical spec now say so. A real fallback rerun with the change completed and the process held only loopback connections (see [live-check.md](live-check.md)). A true boundary would need a network namespace with a forwarded loopback socket and is a follow-up.
- F-003: accepted, see above; changing the overlay for one backend would contradict AC-004.
- F-004, F-005: accepted.

- Verdict: approved

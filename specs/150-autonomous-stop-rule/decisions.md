# Decisions: 150-autonomous-stop-rule

## D-001 (proposal, fix cycle 2): the runner's test check timed out with environmental ledger failures

- **Status**: proposed, agent-provisional; for the next review to decide.
- **Label**: proposed product change (out of this feature's scope).
- **Observation**: the `[checks]` test command `uv run --locked python -m unittest tests/test_*.py` hit its timeout (exit 124, `timed_out: true`). Its truncated output shows errors and failures in the first modules in glob order, starting with `tests/test_agent_run_ledger.py`. After those, it shows long runs of passing tests until the timeout. The cycle 2 fix input lists no review findings and no non-approved verdicts.
- **Local reproduction**: inside this fix step, `tests/test_agent_run_ledger.py` fails with 19 errors and 3 failures. Twenty-one of them raise `ledger.LedgerError: operator attestation is unavailable inside an agent step`. `ledger._operator_step_guard` raises this when `BALLAST_SPEC_WORKFLOW` or `SPECKIT_WORKFLOW_RUN_ID` is set, and the agent step and the check runner set those variables. `tests/test_governance.py`, the only test module this feature changes, passes in the same step: 38 tests, `OK`. Rerunning the ledger tests with both variables unset needed an approval this step cannot get, so the step could not confirm a clean pass outside the guard or measure the suite's duration.
- **Why not fixed here**: no failure is attributable to this feature's diff. Against `main`, it changes only ADR-0004, ADR-0010, the new ADR-0020, `specs/TECHNICAL-SPEC.md`, `templates/policies/spec-kit-workflow.md` and `tests/test_governance.py`. Its new tests only read documents: they add no subprocess, sleep or loop over the repository. Isolating the ledger tests from the caller's environment would be an unrelated change, and the engineering policy forbids mixing one into this feature. So would changing the environment the runner gives `[checks]` commands, or the checks timeout in `ballast.toml`. The runner change is also R2. The same failure was recorded for feature 142 (`specs/142-feature-ui-states/decisions.md`, D-001 and D-002).
- **Proposal**: use the fast gate, run outside an agent step in the operator's terminal or CI, as this feature's test evidence. Track the root cause in one separate Issue, unless one already exists from feature 142. That Issue should make the ledger tests clear `BALLAST_SPEC_WORKFLOW` and `SPECKIT_WORKFLOW_RUN_ID` in `setUp` without weakening `_operator_step_guard`. It should also give `[checks]` commands an environment without the agent guard and the run variables, so the suite runs as it does in CI.

# Decisions

## DEC-0001 — Proposal

- **Found during**: the plan review of Autonomous run `d6b5dff2` (2026-10-06), finding F-001 in [reviews/plan.md](reviews/plan.md). The run blocked at `record-plan-review`.
- **Conflict**: the plan realized FR-007 ("the capture workflow definition that runs MUST be the one on the repository's default branch") by dispatching the workflow on the default-branch ref. That run's job executes PR-head code, which agents write. Any code in a job can obtain the run's Actions runtime token and write Actions cache entries scoped to the run's ref. Every branch and the project's privileged default-branch workflows restore default-branch caches. A feature branch's own CI cannot write that scope, so this would be new reach for agent-written code (BL-INV-003). Splitting the job does not help: the token and its cache scope belong to the run's ref, not to a job's `permissions` or to the actions it uses. The only safe ref for this code is the PR's head branch. GitHub then loads the definition from that branch, which the current wording of FR-007 and AC-010 excludes.
- **Label**: architecture issue (security boundary) that needs a spec wording change; the intent of FR-007 and AC-010 is unchanged.
- **Options**:
  1. Dispatch on the PR's head branch. Before dispatching, require the head commit's `ballast-demo.yml` to have the same Git blob ID as the default branch's, and refuse `workflow-differs` otherwise. Link a result only when the run's `head_sha` is the requested commit (`commit-mismatch` otherwise). Reword FR-007 and AC-010 to this guarantee.
  2. Keep default-branch dispatch and move the command into a separate `permissions: {}` job, with only a size-bounded file handed to an upload job. This does not close the cache path (see the conflict above).
  3. Keep default-branch dispatch and record the cache-poisoning reach as an accepted residual risk in ADR-0012.
- **Needs**: a resolution before tasks are generated, and the spec wording change below before implementation.

## DEC-0001 — Resolution

- **Status**: resolved by the driving agent under the operator's standing authority for v1.0 issues (2026-10-05), listed for merge review.
- **Resolution**: option 1. The design and its reasoning are in [research R15](research.md#r15-execution-scope-of-the-capture-run-plan-review-f-001). The race between the identity check and the dispatch is bounded: the run's `head_sha` postcondition never links a result from another commit, and only a push to the feature branch can move its tip. That push could already run any definition on that branch. Options 2 and 3 leave agent-written code able to write default-branch caches.
- **Spec text that must change** (spec.md is not edited by this decision; the change is made through the spec workflow before implementation):
  - **FR-007**, currently: "The capture workflow definition that runs MUST be the one on the repository's default branch, so a change on the feature branch does not run with the operator's authority." Proposed: "The capture workflow definition that runs MUST be identical to the one on the repository's default branch: Ballast MUST refuse a capture whose feature-branch copy differs, and MUST NOT present a run at any commit other than the requested one as a capture. Code from the feature branch MUST NOT run in a workflow run whose ref is the default branch. A change on the feature branch therefore does not run with the operator's authority, and the capture can write no cache or artifact scope beyond the feature branch's own."
  - **AC-010**, the **Then** clause, currently: "the command and scenario that run come from the protected configuration and the workflow definition comes from the default branch, so the agent's edit does not run with the operator's authority." Proposed: "the command and scenario that run come from the protected configuration; a capture whose feature-branch workflow file differs from the default branch's is refused with a remedy and dispatches nothing; and the capture runs under the feature branch's ref, so neither the agent's edit nor the PR's code runs with the operator's authority or writes a cache scope beyond the feature branch's own."
  - The matching discovery edge case ([discovery.md](discovery.md), "An agent changes the demo workflow file on the feature branch") carries the same old wording and is informational only.
